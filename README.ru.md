# DPT.Engine

DPT.Engine - это движок для демосцен и игр под Windows, переписанный с XNA на .NET Framework
4.0, Win32 и Direct3D 9, поэтому он работает на Windows XP SP3 и на всём, что новее. Проект -
это таймлайн из эффектов: очистка, 2D-слои, 3D-сцены, захват в текстуру, размытие, feedback,
контраст, тряска камеры, частицы. Таймлайн играется с фиксированной частотой кадров в
отдельный внеэкранный буфер и выводится в окно с сохранением пропорций - та же модель, что
была в оригинальном Addict2, и для демосцены она подходит лучше всего. Всё написано на чистом C#
с ручным COM-интеропом и без сторонних зависимостей времени выполнения. Любой сбой
записывается и переживается, а не выбрасывается наружу: нет звукового устройства, не
скомпилировался шейдер, побился один объект в проекте - отключается только этот узел, всё
остальное продолжает работать.

## Возможности

| Область | Что есть |
| --- | --- |
| Графика | Устройство Direct3D 9 через COM-vtable, откат hardware/mixed/software/reference, кэш делегатов и состояний рендера, восстановление после потери устройства |
| Шейдеры | HLSL компилируется на старте через `d3dcompiler_*.dll`, кэшируется в памяти и на диске; если компилятора нет, включается фиксированный конвейер |
| Сцена | Примитивы (куб, сфера, плоскость, произвольная сетка), иерархия по parent-id, материалы со смешиванием/затенением/глубиной, туман, направленный свет |
| Анимация | Одномерные сплайны: step, linear, Hermite, Catmull-Rom, B-spline, синус, пила, меандр; выборка по времени в секундах |
| Таймлайн | Девять типов эффектов, каждый активен на отрезке кадров и имеет анимируемый прямоугольник в виртуальном пространстве 800x600 |
| Проект | JSON-файл со встроенными текстурами, сценами, анимациями и таймлайном; читается и диффится в git |
| Воспроизведение | Цикл с фиксированным шагом по частоте проекта, внеэкранный буфер, вывод с полосами, клавиши F1/F2/F11/F12 |
| Диагностика | Логирование через `System.Diagnostics.Trace` с ротацией файла и кольцевым буфером в памяти, таблица состояний подсистем, отчёты о падениях |
| Инструменты | 38 юнит- и интероп-тестов (графические идут на реальном устройстве), headless-проверка, отдельный self-test |

## Требования

| | |
| --- | --- |
| Операционная система | Windows XP SP3 или новее |
| Среда выполнения | .NET Framework 4.0 |
| Графика | Драйвер с поддержкой Direct3D 9, вершинные и пиксельные шейдеры 2.0 |
| Компилятор шейдеров | Любой `d3dcompiler_*.dll` (от 33 до 47), который найдёт загрузчик; без него движок всё равно запустится на фиксированном конвейере |
| Сборка | .NET SDK 6.0 или новее и пакет `Microsoft.NETFramework.ReferenceAssemblies`, который проекты подтягивают через NuGet |

## Быстрый старт

```bat
dotnet build src/DPT.Engine/DPT.Engine.csproj
.\src\DPT.Engine\bin\Debug\net40\dptengine.exe
```

Запустится встроенный шаблон. Чтобы проиграть свой проект:

```bat
.\src\DPT.Engine\bin\Debug\net40\dptengine.exe path\to\demo.dptproj
```

Ключи командной строки:

| Аргумент | Значение |
| --- | --- |
| `[project]` | Файл проекта. Если его нет или он битый, загрузится встроенный шаблон |
| `--headless` | Выполнить проверку без окна |
| `--log-level=LEVEL` | `verbose`, `info`, `warning` или `error` (по умолчанию `info`) |
| `--help`, `-h`, `/?` | Показать справку |

## Демо-шаблон

`TemplateProject.Create()` собирает демо прямо в коде, поэтому свежий клон репозитория сразу
что-то показывает. Разрешение 1024x768, 900 кадров при 100 fps (девять секунд). Внутри:

* пол 60x60 единиц с тайлящейся синей сеткой 128x128 и туманом от 6 до 34 единиц;
* девять кубов в два уходящих ряда: покачиваются, вращаются и пульсируют синим каналом,
  всё это одна анимация сцены с дорожками вида `nodeId.property`;
* излучатель частиц в центре коридора: 600 частиц, синие искры летят вверх с гравитацией;
* проезд камеры по коридору с лёгкой пульсацией угла обзора, `eyeZ` от -12 до -4;
* шлейф feedback во второй половине таймлайна;
* короткая тряска камеры на кадрах 600-640;
* очистка, захват в текстуру (слот 0) и шаг частиц на всю длину таймлайна, чтобы на каждом
  кадре работали все семейства эффектов.

Две текстуры генерируются процедурно: сетка и мягкое радиальное свечение для частиц.

## Управление

| Клавиша | Действие |
| --- | --- |
| Esc | Выход |
| F1 | Показать/скрыть оверлей (название, FPS, номер кадра, устройство, список клавиш, сбойные подсистемы) |
| F2 | Перезапустить таймлайн и сбросить все излучатели частиц |
| F11 | Полный экран без рамки. Alt+Enter делает то же самое |
| F12 | Сохранить скриншот в BMP в каталог данных, подпапка `Screenshots\` |

Полный экран - это окно без рамки на весь монитор, а не смена режима дисплея: устройство
остаётся оконным, а цепочка обмена просто растягивается на клиентскую область.

## Состояние

Что работает сейчас:

* Устройство Direct3D 9, интероп, обёртки ресурсов, компиляция шейдеров с дисковым кэшем,
  откат на фиксированный конвейер, потеря и восстановление устройства, изменение размера окна.
* Граф сцены, сетки, материалы, туман, двухпроходный рендеринг с сортировкой прозрачных
  объектов, билборд-частицы.
* Сплайны, анимация сцены и камеры.
* Все девять эффектов таймлайна, JSON-формат проекта со встроенными текстурами, сохранение и
  загрузка с нормализацией и починкой данных.
* Проигрывание в внеэкранный буфер с полосами, оверлей, скриншоты, цикл с фиксированным шагом.
* Логирование, fault guard, отчёт по подсистемам, отчёты о падениях.
* 38 тестов и headless-проверка - всё зелёное.

Чего пока нет, прямо и без прикрас:

* **Нет звука.** Нет ни звукового устройства, ни проигрывателя музыки, ни звуковых событий в
  таймлайне. Путь через FMOD/BASS из оригинала не переносился.
* **В рантайме нет сети.** Сетевой протокол, записи сессий и проектов и блокирующий клиент
  лежат в `DPT.Engine.Shared`, мастер-сервер - отдельный проект, но рантайм не открывает
  сокетов: нет ни списка сессий, ни хостинга, ни подключения.
* **Редактора пока нет.** Он задуман как веб-страница (HTML/CSS/JS с таймлайном, списком
  объектов и панелью шейдеров) под небольшим хост-приложением. Ни страницы, ни хоста в этом
  дереве нет, лаунчера тоже. Пока проекты пишутся руками по формату из
  `docs/PROJECT_FORMAT.md`.
* `DPTEngine.slnx` ссылается на `DPT.Engine.Editor` и `DPT.Engine.Launcher`, которых нет,
  поэтому сборка файла решения падает. Собирайте проекты по отдельности, как написано в
  `docs/BUILDING.md`.
* Скриншоты и чтение пикселей работают **один раз на устройство**: второй readback вешает
  драйвер, на котором всё это отлаживалось. Подробности - в `docs/TROUBLESHOOTING.md`.
* Цвета не переживают сохранение и загрузку: писатель выдаёт `#RRGGBBAA`, а читатель ждёт
  `#AARRGGBB`. Подробности - в `docs/PROJECT_FORMAT.md`.
* `display3d` хранит индекс камеры, но используется только одна камера на сцену.
